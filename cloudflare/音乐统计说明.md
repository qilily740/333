## 统计口径

统一以北京时间 00:00 划分日期。后端收到请求的时间决定请求属于哪一天；上游调用按各自开始时间归日，跨午夜可能与所属小手机请求不在同一天。

### 使用设备数

首次实际使用音乐时，生成随机 UUID v4，保存在独立的 `iris-music-statistics` IndexedDB，并在本地存储留一份快速读取副本。首次生成使用读写事务，避免两个标签页各自创建不同标识；不写入角色、用户档案、聊天记录、登录会话或应用备份。能力探测覆盖响应正文，最多等待 500ms，结果短暂缓存 1 分钟。身份存储迟迟不返回时最多等待 150ms；失败则不携带标识，继续音乐操作。

请求头 `X-Iris-Music-Device` 只用于统计，不能用于登录或管理员认证。后端使用独立服务端密钥 HMAC-SHA256 后再存入统计数据库，**不保存原始 UUID**；匿名头不会转发给网易云。

`devices(day, device)` 联合主键保证同设备同日只记录一次；区间使用 `COUNT(DISTINCT device)`，不累加每日设备数。换设备、换浏览器或清除本地数据可能重复计算；它不是使用人数，也不是账号数。匿名标识可以被客户端伪造或重置，不能防刷量、不能当成身份认证。同一浏览器访问不同前端域名/不同部署站点时，本地存储隔离，也可能被重复计算。

无匿名标识或格式错误的请求，单独累计“无标识请求”，不增加使用设备数。本地缓存使用事件没有标识时也单独列出。

### 小手机调用后端

仅统计音乐实际接口，排除 OPTIONS、`/health`、反馈、管理接口、未知路径和统计上报接口本身。按搜索、歌曲信息与歌词、歌曲信息及播放地址、按歌名匹配、歌单详情/同步、二维码、登录状态、退出登录分类。

- `/song?metadata=1`：歌曲信息与歌词。
- `/song`：一次小手机请求，实际工作包含信息、歌词、播放地址；不把它伪造为三次后端接口请求。
- `/resolve` 内部进入 `/song` 时，小手机请求仍只算一次。
- 自动重试是新的实际请求，增加调用次数；同设备仍只算一个使用设备数。
- 2xx/3xx 是接口成功，4xx/5xx 是失败。登录二维码“等待扫码”等正常状态返回 200，算正常查询；成功不是用户最终听到完整歌曲的保证。

### 后端调用网易云等上游

现有全部网易云 fetch 都经两个封装函数，独立记录每次真正发出的上游请求，包括分页、降级、重试、歌词和播放地址。HTTP/解析异常或网易云错误码作为失败；200 及二维码的正常轮询状态作为成功。上游不保存歌曲名、查询词、用户资料、cookie、请求 URL 或正文。

耗时使用服务端 `performance.now()`，展示平均和最大墙钟耗时；并行上游耗时不能直接相加当成整个请求耗时。它不包括浏览器到 Worker 的网络延迟、歌曲 CDN 下载及客户端播放时长。

### 本地 / 缓存事件

实际播放时、连续播放每约 10 秒检查时、查看已缓存歌单时发出尽力上报。每个标签页每个动作每天最多成功上报一次；同一次失败的上报重试复用事件 ID。多个标签页即使分别上报，设备仍去重。

这些事件只补充活跃设备，不增加音乐接口调用次数或上游调用次数。明细中“成功”表示接收了使用事件，不代表整首歌曲播放完毕。离线、屏蔽请求、旧版前端可能漏记这些设备。

### 并发、重复、故障

独立 Durable Object 内使用同步 SQLite 事务，事件去重、设备去重和计数增加同一事务提交，失败整体回滚。服务器对每个实际请求生成事件 ID；后台统计重试复用同一个 ID，避免“已写入但确认丢失”重复加数。上报调用失败最多重试一次，不让它无限消耗额度。

统计使用 `ctx.waitUntil()`，写入失败不阻断搜歌/播放。采集是尽力而为：断网、额度不足、Worker 进程中断、极端故障可能漏记，不能宣称绝对完整。后台只输出固定的 `music_statistics_write_failed`，不输出标识、URL、IP、用户信息或凭证。

## 独立存储与保留期

`MUSIC_STATS` 新命名空间只存以下内容：

- 首次成功采集时间（无事件时为空）。
- 7 天内的随机事件 ID/入库时间，用于去重；不存事件正文。
- 90 天内的日期/HMAC 设备标识，用于区间去重。
- 90 天内的日期/范围/分类聚合计数和耗时总和、最大值。

每日北京时间 00:01 左右的独立清理 alarm 删除过期统计，不操作现有 KV 或应用数据。最早时间是第一次成功入库的实际时间，不伪装成发布当天 00:00。上线前、没有采集记录的日期展示“未采集”，过保留期展示“已过保留期”；值为 null/文字，不填 0。某天只有缓存事件时，已知后端调用数才可以为 0。

所选区间含未采集/过期/今天/起始日时，会标为部分区间，区间去重只覆盖仍有有效数据的部分；不存在的数据不推算。今天固定注明尚未完整。

## 套餐、费用与限制（2026-10-31 查阅）

通过现有 Wrangler 凭证只读查询此 Worker 配置的账号套餐时返回 401，**尚未核实当前账号是 Free 还是 Paid**。发布前需要用有效登录核实。配置文件指定账号与本机旧缓存账号不一致，因此不能直接使用旧缓存判断套餐。

采用 Workers Free 也支持的 SQLite Durable Objects，不使用付费专属的旧 KV 型 Durable Objects、Queues 或 Analytics Engine，不创建订阅、不升级套餐。当前没有实际开通/发布任何资源。

按 Cloudflare 当前文档：Free 包含每天 100,000 次 DO 请求、13,000 GB-s 执行时间、5,000,000 行读取、100,000 行写入；总 SQLite 存储 5GB，单对象 1GB。配额与账号其他用量共享，重置时区是 UTC，**统计日期仍为北京时间**。超额会让统计操作失败，不会自动升级套餐。

本地/缓存使用事件会额外消耗原 Worker 的请求额度；原 Worker 自己的账号级配额如果耗尽，仍会影响服务，这不等同于统计写入故障。一次音乐请求通常对应一次 DO 上报；失败重试会额外增加 DO 请求。一次上报会写事件去重记录/索引、分类计数，首次日活设备还会写设备记录；每次上游尝试也更新一条聚合。清理删除、索引及查询也消耗额度，不能按“一次请求只写一行”估算。流量尚未提供，无法承诺任意访问量都免费；建议先观察免费配额，接近上限时停止采集/降低保留天数，再评估方案，不能自行开通付费。

如果账号原本就是 Paid，超出其内含额度仍可能产生用量费用：DO 请求 $0.15/百万，SQLite 行读 $0.001/百万、行写 $1/百万，存储 $0.20/GB-month；还有执行时间及原 Worker 本身的费用。单个计数对象在突发高流量时会串行，可能过载，当前实现不面向超大流量集群。

来源：[Durable Objects 定价](https://developers.cloudflare.com/durable-objects/platform/pricing/)、[配额与限制](https://developers.cloudflare.com/durable-objects/platform/limits/)、[Workers 定价](https://developers.cloudflare.com/workers/platform/pricing/)。以发布时 Cloudflare 控制台实际套餐和最新规则为准。
