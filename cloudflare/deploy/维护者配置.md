# Iris 公共部署服务（仅维护者设置一次）

用户部署 GitHub 前端后，在「设置 → 部署」选择连接方式：使用 Iris 公共服务时无需 Cloudflare 账号；自己搭建时才登录 Cloudflare，可选 workers.dev 默认地址或自己的域名。手机不需要安装工具或输入命令。

维护者的 OAuth 域名验证只证明 Iris 授权应用归维护者所有，不限制用户前端和后端的域名。每个 GitHub 项目路径和自有域名都可以使用同一个授权服务，授权后返回原页面。

公共服务地址在 `config/deployment.json` 的 `publicServices` 中配置。维护者的公共通知服务需启用 `ALLOW_PUBLIC_FRONTENDS=true`，允许其他 HTTPS 前端连接；设备凭据、数据加密和调用限额仍然生效。用户自建包默认只允许自己的前端访问。

## 注册 Iris 授权应用

在 Cloudflare 的 Manage Account → OAuth clients → Create client：

- 名称：Iris
- Client URL：`https://iris-public.suri.us.ci`（维护者自己的、可以验证所有权的域名）
- Redirect URL：`https://iris-deploy.weishengrongqing.workers.dev/oauth/callback`
- Response type：`code`；Grant type：`authorization_code`
- Token authentication method：`none`（PKCE）
- Scopes：`account-settings.read`、`workers-scripts.admin`、`workers-kv-storage.write`、`workers-routes.write`、`zone.read`

自己的账号测试可先用 Private。要让其他账号使用，需按 Cloudflare 提示验证 Client URL 域名并把应用设为 Public。仅有 Private 应用不等于向所有用户开放。

把生成的 Client ID 填入公共 Worker 的 `CF_CLIENT_ID`。Client ID 可以公开；PKCE 客户端不需要 Client Secret。如果改用 confidential client，只能使用 `client_secret_post`，Secret 存在 Worker Secrets。

## 公共 Worker 配置

`wrangler.jsonc` 定义新的 Iris Deploy Worker 和 SQLite Durable Object，不复用作者音乐、通知后端的存储或密钥。`DEPLOY_VAULT_KEY` 是 32 字节随机密钥（base64url），作为 Worker Secret 保存。不要把它放进前端或提交到 Git。

`config/deployment.json` 中的 `serviceUrl` 是所有前端使用的授权服务。`PUBLIC_URL` 必须与它保持一致。服务 `/health` 在授权配置未完成时明确返回 `ready: false`，前端不会显示已登录或部署成功。

发布前运行后端代码包生成脚本、检查生成包与公开源码一致、部署 Worker。该维护者构建步骤不出现在普通用户界面里。

## 运行方式

- 浏览器只保存绑定当前前端来源的部署会话凭据，Cloudflare access/refresh tokens 不返回前端、不进入聊天备份。
- Cloudflare 授权使用随机 state、PKCE 和固定回调；回到发起的 GitHub 页面时只带会话 ID，不携带 Cloudflare Token。
- 后端包由维护者固定，不接受第三方上传代码或任意 Cloudflare API 路径。
- 用户自己的 Worker、KV、Durable Objects 都建在用户授权的账号中，使用该账号的额度。项目名称冲突会停止，不覆盖其他 Worker。
- 云端凭据及生成的服务密钥加密存储，会话 30 天后清理。取消保留已经创建的资源；断开授权撤销凭据，不删除用户后端。
