# 人物与成就

入口：经历 → 第四个小类目“人物与成就”。顺序仍为人生时间线、成长档案、地球地图、人物与成就、IF 世界，最后一项仍保留原占位功能。

## 页面与操作

- 两个内部切换项为“人物评价”“奖项成就”，使用 Iris 现有轻灰分隔、常规字重和黑白收藏卡样式。
- 人物列表展示姓名、身份、关系和评价数。进入人物后可查看按阶段排列的评价、来源和关联经历，支持阶段筛选。
- 支持手动新增人物、评价、奖项，编辑与删除；编辑使用居中原生 dialog，字段区内部滚动。人物删除会明确询问是否同时删除其评价。
- 每条评价可单独重生成，保留 ID、原阶段和其他记录。失败或返回无效内容时旧评价不变。
- 奖项分正式与趣味，使用边框、纪念章及明确文字区分，可按阶段和类型筛选；详情展示原因、颁发者、来源及关联经历。
- 关联只使用稳定经历 ID。目标经历删除或不再确认时，人物评价/奖项仍保留并显示关联失效。
- 无资料、无评价或无奖项均有空状态及手动添加入口；不会创建占位人物或荣誉。

## 生成与校验

经历下五个小类目统一使用 **经历 API 配置及所选模型**，通过共用 `runtime.analyze`、`requestConfiguredChatCompletion` 和 JSON 模式请求；不回退聊天接口，不新增地址、密钥或地图/识图服务。IF 世界当前仍是无 API 的占位页。

只有点击“从设定生成 NPC 评价”“生成奖项成就”、指定人物的生成或单条评价的重生成时调用一次 API。打开页面、筛选、查看、增删改均不调用 API。请求失败不自动重试。同一角色同时只允许一个生成任务，离开页面或切换角色后任务仍写回原角色；原角色已删除/替换或来源材料已改变则停止保存。

取材复用当前角色的 `worldBookPromptValues`、人设、已确认人生时间线，以及用户手动录入的 NPC 资料；不加入其他角色的私有人设、待确认时间线或推演旅行事实。无时间线时仍可依靠人设/世界书的明确阶段生成，精确年龄缺乏依据时留空。

前端解析支持 JSON 代码围栏、前后说明文字及常见聊天响应包装。无效记录按条过滤，整体解析失败保留已有档案。新 NPC 必须有真实原文且包含姓名/称呼；重要亲属关系要有关系原文。别名需原文明确称呼关系，不能仅凭共现合并。NPC 认识起点、评价阶段与关联经历做时间校验；未来经历不能作为早期评价关联。提示词进一步约束各 NPC 的当时知识、性格、表达和立场。

已有事实奖项须有包含奖名的真实引文。AI 创作奖项保存 `ai-created` 来源，正式创作奖项的颁发者必须标为虚构，详情明确说明不是现实授予记录。用户手动记录保留手动来源。阶段与奖项数量随设定而定，不填充固定配额。

语义层面的角色口吻、共同经历真实性和机构现实身份主要依赖模型遵守提示及用户后续编辑；不能仅凭 JSON 校验证明这些叙事事实。

## 数据和备份

数据位置为每个角色的 `peopleAchievements`：

- `schemaVersion: 1`、`ownerId` 对应 `experienceCharacterId`。
- `npcs`：稳定 ID、姓名、别名、身份、关系、性格/表达、相识年龄/年份/阶段、来源、原文、手动/AI 标记、创建及更新时间。
- `reviews`：稳定 ID、NPC ID、阶段/年龄范围/年份、正文、经历 ID 数组、当时依据原文、来源、创建及更新时间。
- `awards`：稳定 ID、名称、正式/趣味、阶段/年龄范围/年份、颁发者及虚构标记、原因、经历 ID 数组、来源/原文、事实/创作/手动标记、创建及更新时间。
- `deleted`：按集合保存删除墓碑，合并旧备份时避免恢复已删除人物和评价。

沿用现有 IndexedDB / IrisStorage 原子保存和失败回滚。人物档案独立于角色人设、世界书、聊天记忆和其他经历类目。

完整 JSON/ZIP 备份自动包含数据；设置 → 数据备份新增独立“人物与成就”分类和清单计数。分类导出保留角色稳定身份，不携带无关聊天/人设；分类恢复按稳定角色身份对应，不依靠数组位置。同一条记录按更新时间合并，同时遵守删除墓碑。旧备份缺少该分类时兼容；恢复旧角色资料不清空当前人物档案。损坏归属、重复记录和无效结构会在导入前拒绝。

## 实现文件

- `scripts/people-core.js`：数据、材料、提示词、解析校验、增删改、保存回滚。
- `scripts/people.js`：页面、筛选、模态编辑、详情及按角色后台任务。
- `scripts/experiences.js`、`scripts/app.js`：第四类目、角色切换和现有聊天请求接入。
- `scripts/backup-core.js`：完整/分类备份、恢复、合并与校验。
- `scripts/storage-bootstrap.js`、`index.html`：新增脚本及缓存版本 r64。

## 验证范围

已通过 84 项相关测试，使用 Node + jsdom 模拟核心数据、完整入口、手动 CRUD、保存失败保留输入、单条重生成、阶段筛选、角色切换、后台生成、每次按钮单请求、统一经历模型路由、JSON/ZIP 备份及旧备份兼容。相关地球、成长档案和时间线备份回归也通过。

未调用用户真实 API，未做真实手机、Safari/Chrome 浏览器视觉与软键盘验证；生成文本的实际质量和具体模型兼容性尚需实测。未部署。

接口统一更新（r65）：人物评价、指定人物评价、单条重生成、奖项生成均改用经历页面共用analyze方法，严格使用经历API与模型，无配置时保留资料并报错，不回退聊天。已通过不同聊天/经历配置并存时的真实应用入口模拟验证。
