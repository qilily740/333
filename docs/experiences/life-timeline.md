# 人生时间线 · 第一阶段

本地入口：主页功能菜单 → **Experiences** → **人生时间线**。其他横向类目可切换查看占位页，顶栏中文随当前类目联动；本阶段不实现其业务功能。

## 使用

点击顶栏右侧头像切换角色。全部、已确认、待确认的数量与排序、拾光成线入口放在同一行；顶部不再提供新增按钮。用拾光成线整理经历后，点击条目可编辑、查看完整资料或删除，可在编辑面板中点击保存右侧的“确认”直接保存并确认；只点保存会保留原状态，已确认条目显示“已确认”。条目默认仅显示一行描述与简短地点；完整内容不截断，可展开查看。编辑面板采用并排字段，来源折叠在“来源与补充”中。描述不限制内容；年龄、日期、地点可留空。保存失败时保留表单草稿并回滚对已保存记录的修改。删除需确认。

AI 整理后默认按年龄升序。年龄排序使用明确填写的开始年龄（缺省时使用结束年龄）；旧 AI 草稿中“五岁”等明确中文年龄也能用于排序，出生事件从 0 岁开始。用户主动清空年龄后保持为空，不重新补回。日期排序仅识别明确的年份、年月、年月日。不使用生日、人设或聊天记录推算时间。“约某年”等自由文字原样保存，排序时作为未确定时间处理。无时间的经历仍可保存，切换“手动排序”后用上移、下移调整。手动顺序和排序方式按角色保存。

## 拾光成线（API 整理）

小尺寸深灰按钮位于排序控件右侧，与状态筛选同排。可在“设置 → API 配置 → 功能模块 → 经历”为整个经历模块共用分配接口与模型（兼容旧时间线配置）；未单独分配时沿用聊天接口或当前默认接口。仅点击按钮后发送当前角色资料及该角色已有经历（用于去重），不发送其他角色资料、世界书或聊天记忆。

只提取有逐字原文依据的人生事件，全部标记为“待确认”。未明确的年龄、日期和地点留空；不计算出生年份或推断缺失经历。接口返回格式错误或没有原文依据时不保存。每次点击都可重新生成：新结果替换上一轮尚未确认且未经手动编辑的 AI 草稿，已确认、手动编辑、手动记录及当前正在编辑的经历保留。失败、空结果或全部与保留记录重复时保留原草稿；分析期间切换角色或修改原始资料后，旧结果不会写入。可点击草稿修改并确认。

## 数据与持久化

沿用 `state.characters`，每个角色新增稳定标识 `experienceCharacterId`；经历保存在该角色的 `lifeTimeline`，不依赖角色数组位置。角色切换、删除或对象替换后，旧表单不可再写入。

```json
{
  "experienceCharacterId": "role-<unique-id>",
  "lifeTimeline": {
    "schemaVersion": 1,
    "ownerId": "role-<unique-id>",
    "sortMode": "age",
    "entries": [{
      "id": "<unique-id>",
      "title": "入学",
      "description": "自由描述",
      "type": "学习",
      "startAge": null,
      "endAge": null,
      "date": "",
      "location": "",
      "source": "手动录入",
      "status": "confirmed",
      "createdAt": 0,
      "updatedAt": 0,
      "order": 0,
      "extensions": {}
    }]
  }
}
```

时间戳单位为毫秒。`schemaVersion` 与 `extensions` 保留扩展空间。API 草稿在 `extensions` 中记录 `origin: "ai-draft"` 和原文 `evidence`；不实现地图或分支逻辑。

通过现有 `IrisStorage.save` 写入：优先为 IndexedDB 数据库 `iris-local-data`、对象仓库 `app-state`、键 `main`；IndexedDB 不可用时沿用 `localStorage['iris-v1']` 后备机制。只有写入成功才显示保存完成。不改写角色人设、世界书、线上/线下聊天记忆。

## 导出、导入与备份

设置 → 存储 → 共用资料新增“人生经历时间线”。完整备份默认包含时间线，也可只勾选这一类。沿用 JSON / ZIP、SHA-256 完整性校验和恢复预览；预览显示经历条数。

- 合并恢复：按角色稳定身份匹配。同一条经历按 ID 去重，较新的更新时间保留整条记录，避免空字段被旧内容补回。
- 分类替换：只替换备份中明确包含时间线的角色；未包含的角色经历及其他资料保留。
- 旧备份：支持格式 2、3、4；没有时间线字段时不清空现有经历。没有稳定 ID 的旧角色只在名称等可用身份字段唯一匹配时关联；不确定时保留为独立角色，避免猜测覆盖。
- 身份顺序：角色或用户顺序变化时，同时映射聊天、短信、邀约等数据的索引，避免把旧数组位置当成角色身份。
- 完整替换：替换备份覆盖的本地内容，保留其他角色资料及备份未包含的时间线；界面确认文字已说明此行为。

## 验证

纯逻辑与备份测试：

```sh
node --test tests/timeline-core.test.cjs tests/timeline-backup.test.cjs
```

`timeline-ui.test.cjs` 和 `timeline-app-integration.test.cjs` 使用可选的 jsdom；未安装时会明确跳过。本次在临时目录安装 jsdom 后，通过 `NODE_PATH` 运行，覆盖真实应用入口、表单、过滤、删除确认、角色切换、保存失败和重新打开后的恢复。

手机适配包含五个等宽类目同排、筛选与排序同排、头像选择器、可收缩的表单控件与长文本换行；本次本机浏览器预览未获授权，尚未进行实际手机截图验收。

## 本阶段不包含

成长档案、地球地图与路线、人物评分等额外 AI 评估、奖项与成就、NPC 评价、IF 支线。应用版本号保持原值，代码仅保存在本地。
